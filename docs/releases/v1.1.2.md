## Track check: crashes found before the game finds them

- **Objects that need a route** (moving boxes, cars, boats, penguins, sound emitters and others) are reported as errors when they have none. Such an object reads its route without checking it, so the game crashes with *Invalid read from 0x00000000*. **Create a route for each** fixes them in one click, an object added in the editor gets its own route at once, and the Inspector says when the selected object needs one.
- **Missing object files**: an object whose model (`.brres`, `.kcl`) is not in the SZS is an error, and missing effects or animations are warnings. The list of files each object needs comes from Wiimm's SZS Tools. Files the editor copies from the tracks folder when saving, or that Common.szs provides, are not reported.
- **Cannons** in the collision without a cannon destination (CNPT) are errors: the game crashes when a kart touches them.
- Also checked: collision that needs `ice.brres`, intro and selection cameras that do not exist, camera areas without a camera, area links to missing enemy points, routes shared by a camera and an object, smooth object routes of two points, more than one goal camera, and invalid stage settings.

## Saving checks the track first

When the track check finds errors, a window lists them before anything is written, with their one-click fixes, **Show in Check panel**, **Cancel** and **Save anyway**. Warnings stop the save too, unless **Also stop for warnings** is turned off in that window.

## Object documentation: required settings and routes

- A setting can be marked `"required": true`: the object does not work while it is 0. **Check** warns about placed objects that leave it at 0, and the Inspector marks it.
- An object can say `"route": { "required": true }` (or `false`), with an optional description. The default documentation states it for every object that needs a route. Documentation that does not say falls back to the list of Wiimm's SZS Tools, so older files keep the crash check.
- **Edit JSON…** has a **Route** choice for each object and a **Required** box for each setting. **Help › Object documentation** and the example file explain both fields.

## Model import

- Fixed **"ABMatt failed … Incorrect name offset"** when importing a model into a track whose `course_model.brres` has SCN0 lights or fog that ABMatt cannot read. ABMatt now only sees the models, textures and texture animations. CHR0, CLR0, SCN0, SHP0, VIS0 and unknown resources are set aside and put back unchanged, byte for byte, which also keeps them from being re-encoded. This applies to OBJ, FBX, glTF, DAE, BLEND, STL and PLY imports, model parts from other tracks, duplicating, deleting and exporting.

## Minimap (beta)

- **Paint anywhere**: the whole area a map can show is now a canvas under the track, so a map can have shapes away from the collision (outlines, ground, water…). A tile painted all in one colour costs two triangles in the game. Where the track lies, painting colours the track and not the canvas under it as well. **Fill** on an empty place fills the whole background.
- A dashed line shows exactly what the **In game** panel shows: the frame fitted into the square map, so on its shorter side a little more than the frame is visible. **Fit view** keeps it in view.

## Settings and About

- **Settings** opens with the editor's version and **Check for updates**, with the same download and install buttons as **Help › About**.
- The **Credits** name in About opens WiiListZ's GitHub profile. The About window no longer opens with a focus outline on it.

## Validation status

The automated tests pass, including new ones for the track check, the object documentation fields, the minimap canvas and the ABMatt import of a track with SCN0. The save window, the route fix, minimap painting outside the track and Apply were checked in the editor on a track that crashed the game because of two wooden boxes without a route; after the fix, Wiimm's SZS check reports no warnings.
